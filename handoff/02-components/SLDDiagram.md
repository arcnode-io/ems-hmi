# SLDDiagram

Tier 1 · Topology view

> Full-screen pan/zoom SVG of the deployment's single-line electrical diagram. The SVG itself is generated by `edp-api` per deployment; the HMI binds live MQTT measurements to element IDs and animates particle flow on energized buses.

See it live in the [gallery](./index.html#sld-diagram).

---

## Architecture

```
edp-api ──── POST /topology ─→  SVG artifact (per deployment)
                                       │
                                       ▼
                              packages/web/.../sld.svg.cache
                                       │
        DTM.buses[] ─────────────────┐ │
        AsyncAPI device_ids ─────────┤ │
                                     ▼ ▼
                                 SLDDiagram (HMI)
                                       │
                                       ▼
                                  Live MQTT
                                       │
                                       ▼
                              animated overlays
```

The SVG is **not hand-drawn per deployment.** It's generated. The HMI's job is purely to render it + animate per live data.

## Props

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `svgUrl` | `string` | required | URL of the EDP SVG artifact (cached locally) |
| `deviceStates` | `Record<string, DeviceState>` | required | Keyed by `device_id`; contains `status`, `runMode`, `kW`, `soc`, `breakerState`, `maintenance`, `acknowledged` |
| `busStates` | `Record<string, 'energized' \| 'deenergized'>` | required | Keyed by bus name from DTM |
| `simMode` | `boolean` | `false` | Adds the SIM watermark |
| `onDeviceTap` | `(deviceId: string) => void` | required | Navigates to module detail |
| `selectedDeviceId` | `string \| null` | `null` | Highlights one node + shows inspector |

`DeviceState` shape:
```ts
interface DeviceState {
  status: 'ok' | 'warn' | 'alarm' | 'fire' | 'maintenance' | 'offline';
  acknowledged: boolean;          // for warn / alarm flashing
  runMode?: string;                // displayed if present
  kW?: number;                     // signed; drives particle direction
  soc?: number;                    // shown on BESS nodes
  breakerState?: 'open' | 'closed' | 'trip';  // drives breaker symbol swap
  maintenance: boolean;
}
```

## States — per device node

| State | Node visual | Flash? | Particles on attached bus? |
|-------|-------------|--------|----------------------------|
| `ok` | status-ok stroke, status-ok indicator | no | yes |
| `warn` (acknowledged) | status-warn stroke + indicator | no | yes |
| `warn` (unacknowledged) | status-warn stroke, indicator flashes opacity 1↔0.3 @ 1Hz | indicator only | yes |
| `alarm` (acknowledged) | status-alarm stroke + indicator | no | yes |
| `alarm` (unacknowledged) | status-alarm stroke, indicator flashes | indicator only | yes |
| `fire` | status-fire stroke + pulsing indicator (opacity 1↔0.6 @ 800ms) | indicator pulses, always | yes |
| `maintenance` | panel fill, status-maintenance dashed stroke, wrench overlay | no | **no — bus de-energized regardless** |
| `offline` | status-offline stroke + indicator | no | **no** |

## States — per bus

| State | Line | Particles |
|-------|------|-----------|
| Energized | domain color, solid | ~3 particles, speed = `clamp(8, 80/\|kW\|, 80)` px/s |
| De-energized | `statusOffline`, solid | none |
| Maintenance (either endpoint) | `statusOffline`, dashed 4-3 | none |
| Reduced motion (any energized) | domain color, solid | replaced by single static arrowhead at midpoint |

## States — breaker symbols

| State | Visual |
|-------|--------|
| Closed | circle + horizontal bar |
| Open | circle + angled gap line |
| Trip | circle + angled line, status-alarm stroke |

## Particle flow contract

The animated particle stream is what makes the SLD read as "live" vs. "schematic." Without motion, an SLD is a static drawing. The contract:

- **Direction:** sign of `kW` on the source-side device. Positive `kW` = source → sink along the bus geometry (from device A coordinate to device B coordinate). Negative reverses.
- **Speed:** linear map of `|kW|` to dot velocity over `[8 px/s, 80 px/s]`, clamped. 50 kW visibly slower than 5 MW; 5 MW does not strobe.
- **Spacing:** ~24px between particles along the path. Maintained via `<animateMotion begin="-Ns">` staggering.
- **Particle visual:** 3px circle, white-tinted at 85% opacity (works against any bus color).
- **Layer order:** particles below interactive overlays, above bus line.

## Accessibility

- The SVG is **decorative for AT.** Screen readers do not navigate the SLD.
- Accessible path: the same module nav is available through `<ModuleCard>` list at `/modules`. Operators relying on a screen reader use the card list.
- `aria-label` on the SLD wrapper: `"Single line diagram. {N} modules. {M} active alarms. Use the modules list for accessible navigation."`
- `prefers-reduced-motion: reduce` → particles replaced by a single static directional arrowhead at the bus midpoint. Numeric values unaffected. Indicator flashes become static state colors.
- Tap targets on nodes: ≥ 44×44 (Rule 6). Pad the SVG hit area with transparent rect if the visible node is smaller.

## Mobile

- Full-screen pan/zoom via `react-svg-pan-zoom` (or RN equivalent on mobile).
- A compact **module badge strip** pinned at the top is the fast-tap alternative — operators tap a badge to jump to a module without panning.
- Initial fit: scale-to-fit on first render, then `react-svg-pan-zoom` controls.

## Don'ts

- ❌ **Never animate the node body fill.** Only the indicator dot flashes / pulses (Rule 3.3). The node fill must stay readable during a flood.
- ❌ **Never use status colors on the bus lines** for non-alarm meaning. Bus color = domain. De-energized = `statusOffline` (gray, not red).
- ❌ **Never invent device IDs.** They come from the DTM. If a node's `id` doesn't match a `device_id`, the binding is a bug — log it but don't render.
- ❌ **Never run particle animation when `prefers-reduced-motion: reduce`.** Replace with the static arrowhead.
- ❌ **Never style the SIM watermark above 10% opacity.** It must not block interaction or compete with status colors.
- ❌ **Never embed measurement values inside the SVG.** Render them as positioned HTML overlays on top of the SVG (better text shaping, easier theming, easier ARIA).
