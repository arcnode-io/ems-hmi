Component Gallery

Every primitive and composition the EMS HMI uses, rendered in both themes, with every state. Each section pairs the visible mock with the tokens it consumes — the engineer wires these names directly into useTheme(). The five primitives (Reading, Indicator, Mode, Gauge, RangeIndicator) are the base set; every higher-tier component composes them.

Tier 0 · Primitive · type: float

Reading

Renders a numeric measurement with its unit. The most common HMI element — every float measurement uses this. Variants change the size + weight for KPI vs. table vs. hero contexts. Missing data renders as "—", never "0" — zero is a valid measurement.

Tier 0 type: float Rule 3.4 · no-data is "—"
Rule 3.4 (was DS-003). No-data renders "—" in textMid. Never "0". Zero is a real measurement; missing data is distinct and must look distinct.
Tier 0 · Primitive · type: bool

Indicator

A colored dot. Color is the entire signal — no label needed. Used in tables and compact rows where space is at a premium. true = OK (green), false = fault (red), null = no data (gray).

Tier 0 type: bool
Tier 0 · Primitive · type: enum

Mode

Colored dot + humanized string. The dot is driven by x-severity on the enum value in the AsyncAPI spec; severity: ok/warn/alarm → statusOk/Warn/Alarm token. Pure mode enums without severity (e.g. control_mode) render with a neutral gray dot — the label carries the meaning.

Tier 0 type: enum
Tier 0 · Primitive · bounded float (radial)

Gauge

Radial measure of a bounded float — SoC %, chiller capacity %, PUE. Domain color comes from colorBess / colorCompute / colorThermal etc — never status colors, because high utilization is the desired state, not an alarm. No-data renders as the gray track only.

Tier 0 bounded float Use domain color, never status
Tier 0 · Primitive · bounded float (linear)

RangeIndicator

Horizontal version of Gauge. Used in measurement rows and per-server table cells where vertical space is the constraint. Threshold marks render as 1px ticks in statusAlarm when the underlying measurement has alarm bounds.

Tier 0 bounded float
Tier 1 · Alarm visual primitive

StatusBadge

The cornerstone alarm-visual primitive. Variants drive both color and icon shape — color alone is never the signal (a11y, color-blind). Each severity has a distinct icon: warn = caution triangle, alarm = warning octagon, fire = flame. Unacknowledged warn/alarm flash opacity. Fire pulses always.

Tier 1 Rule 1 · status RESERVED Rule 3.2 · fire pulse not flash Rule 3.8 · interactive variant
Rule 3.8 (was DS-010). An informational badge has no chevron and no onPress. An interactive badge has a trailing › chevron, cursor: pointer, focus ring, and a required onPress handler (typecheck-enforced). Never mix.
Tier 1 · Composition

KPITile

Compact metric tile — value + unit + label + optional sublabel + trend arrow. Designed to fit three in a 120-px wide card and never wider than 240px. Value uses kpiValue from the type ramp, label uses kpiLabel (uppercase, tracked).

Tier 1 · Composition

ModuleCard

Compact representation of a device-0 (module-tier device). Icon + display name + type label + status badge + up to 3 measurement rows + alarm count. Maintenance mode overlays a wrench label and dims content; the card border switches to statusMaintenance.

Tier 1 Maintenance overlay
Tier 1 · Alarm surface

AlarmRow

Single row in the active alarm panel and historical alarm table. Severity icon + device + alarm name + measurement + age + ack button. The leading pulse dot and the left border are the unacknowledged-state signal — the value and row background do NOT change color (Rule 3.3 / Hollifield §7.18 Method 3).

Tier 1 Rule 3.3 · flash indicator only Rule 3.1 · ack flow
Rule 3.3 (was DS-004). Only the indicator dot + the left border flash. The numeric value, the row background, and the device name stay readable. Flashing values during an alarm flood are unreadable. The brain reads the flash channel separately from the value channel — keep them separate.
Tier 1 · Topology view

SLDDiagram

Single Line Diagram — the live topology of the deployment. The SVG is generated by edp-api from the sizing payload, served alongside the DTM. The HMI binds MQTT measurements to SVG element IDs (matching device_id slugs). Bus connections render animated particle flow when energized; static dashed lines when de-energized or in maintenance.

Tier 1 Rule 5 · reduced motion replaces particles with arrowheads SVG + MQTT
Live power flow. Every energized bus carries an animated particle stream whose direction = sign of kW on the source-side device and whose speed is proportional to |kW| (clamped to 8–80 px/s). Under prefers-reduced-motion: reduce, particles are replaced by a single static directional arrowhead at the bus midpoint. Numeric readouts on nodes are unaffected.
Element binding contract (owned by EDP). Every animated SVG element has id="<device_id_slug>". Bus connection lines have id="bus-<bus_name>". The HMI never invents IDs — it reads them from the DTM buses[] block and the device instances in the AsyncAPI spec.
Tier 2 · Detail page

MeasurementRow

Standard row for displaying a named measurement inside a module detail page. Composes one of the five Tier 0 primitives. Optional inline sparkline of the last-N samples. Row height 38px (SIZE.tableRow).

Tier 2 · Compute detail

GPUHeatmap

Grid of cells, one per GPU slot, color-coded by utilization %. Critical rule: the color ramp uses colorCompute (blue) family — high utilization is the desired state, never amber/red. Idle cells render as outlined gray with "—".

Tier 2 Rule 1 · domain color, not status
Tier 2 · Operator control

CommandPanel + ConfirmationModal

All commands to physical hardware route through CommandPanel → ConfirmationModal. Never a single loose button. The modal is draggable, summarizes the command and target, and labels its primary button Send (SIM) with statusSim color when the deployment is in SIM mode.

Tier 2 Rule 3.1 · two-step confirm
Rule 3.1 (was DS-005). Two-step confirmation is non-negotiable. A misclick must never dispatch a command to hardware. The confirm button enters a pending state until an MQTT acknowledgment arrives or 10s passes.
Tier 3 · Data viz

TimeseriesChart + Histogram

Both charts MUST render alarm thresholds as dashed statusAlarm reference lines labeled MIN / MAX. Any chart whose right edge is live MUST render a vertical dashed NOW marker in textMid. Forecast series are dashed, at chartForecastAlpha opacity. Outlier bins in a histogram render in statusAlarm; in-range bins in the domain color.

Tier 3 Rule 3.6 · thresholds + NOW marker
Rule 3.6 (was DS-008). Without anchored thresholds, "spread of 142 mV" is uncalibrated. Without a NOW marker, "now" is inferred from line geometry. Both are pre-attentive cues, not chrome.
Tier 3 · Analyst

ChatBubble + PrebuiltQueryCard

User and agent variants of chat messages. Prebuilt queries are tappable cards that populate the chart AND send the message in one action — the chart and chat are always connected. Agent responses can add series to the chart; chart selections pass as context to the next message.

Typography ramp

Every text element resolves to one of 11 type roles. Font family is theme-driven; size / weight / line-height / tabular-nums come from the ramp.

Cross-cutting

Elevation

Five levels, strictly tonal with 1px hairline highlights and (on raised levels) thin drop shadows. No heavy shadows. No blur. Light theme adds a subtle white inner-top highlight; dark theme uses a faint top hairline.
