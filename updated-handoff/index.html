This package is the contract between design and engineering for the EMS HMI. Tokens are typed and live in one TypeScript module. Components have one anatomy, one props contract, and a known state matrix. Screens are the same mocks the designer ships from — not redrawn.

Audience Claude Code 4.7 + human reviewer Source tokens.ts (single) Stack React + RN-Web Themes Sovereign · Solarpunk
Stack
Tamagui is out. Tokens authored as a TypeScript module (tokens.ts) consumed via useTheme(). Components use React Native primitives (<View>, <Text>, <Pressable>) — they render natively on mobile and through react-native-web on web. tokens.dtcg.json and tokens.css are generated artifacts for designer / non-React consumers; never edit them by hand.

How this handoff is organized

One source per artifact. Tokens live in tokens.ts. Everything else generates from it or references it. There is no parallel YAML, no Figma export, no hand-maintained JSON. When tokens change, run npm run tokens:generate and commit the regenerated outputs together.

Specs are next to the thing they spec. Each component's .md sits in 02-components/ alongside the gallery that renders it. State matrices reference real DOM in the gallery, not a separate Figma frame. The Playwright suite uses both as fixtures, so a change to the spec automatically tightens the test.

The constitution sits above the component layer. Hard rules apply regardless of which component is involved. Per-component .md files cite the relevant rule numbers; the constitution is the index.

  • Token added? Update tokens.ts, both themes, regen, commit.
  • Component added? Add a .md, add it to 02-components/index.html, add visual + acceptance specs.
  • Rule changed? Update 00-constitution.md; ripple to affected component .md files; bump component versions if the contract changed.
  • Screen changed? Update the mock in 03-screens/; re-baseline the visual spec; verify per-component specs still hold.
